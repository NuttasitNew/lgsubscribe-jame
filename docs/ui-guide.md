# Public UI reference

Use this page as the small index for the public site. The implementation remains the source of truth.

- Stack and tokens: `app/globals.css` defines colors, type, `container-page`, `section-space`, `eyebrow`, and `page-hero`. Check the relevant Next.js guide in `node_modules/next/dist/docs/` before editing framework behavior.
- Public shell: `app/(public)/layout.tsx` composes `components/site-header.tsx`, `components/site-footer.tsx`, `components/floating-line-contact.tsx`, and `components/mobile-dock.tsx`.
- Primitives: `components/ui/button.tsx` for actions, `components/ui/badge.tsx` for labels, `components/ui/card.tsx` for framed content. Example: `feature/public/products/components/product-detail-page.tsx`.
- Product details: `feature/public/products/components/product-detail-page.tsx` owns the section order; `product-gallery.tsx` handles product image navigation; `product-specifications.tsx` displays verified specifications. Route: `/products/[slug]/`.
- WashTower reviews: `feature/public/products/components/wash-tower-reviews.tsx` shows four photos of WT1410NHEG, verified by a readable model code on its carton. WT1410NHEN shows a customer photo matching its navy/beige finish plus two WashTower carton delivery photos that do not show a machine. WT2520NHEN is withdrawn from the October sales catalog. Do not label these three photos as an exact model or a single installation job. Other albums remain unpublished. Images load lazily. Do not present photographs as written customer testimonials.
- Monthly sales availability: `lib/oct-subscription-campaign.ts` uses the October workbook in `data/Price list_Oct.xlsx`; `lib/catalog-products.ts` publishes only matched current models. `lib/promotion-image-assets.ts` maps 67 reviewed October artworks to 68 products, including the shared WD516AN/WD518AN image. Withdrawn, paused, Control Stock and unmatched models have no sales detail route or sitemap entry. Knowledge guides and historical specifications are retained separately.
- Catalog search: `feature/public/products/components/product-catalog-browser.tsx` keeps query and category in the URL; `components/product-card.tsx` carries those filters to the detail route, and `feature/public/products/components/product-catalog-back-link.tsx` restores the filtered listing.
- Representative public pages: `feature/public/home/components/home-page.tsx` shows the homepage review and product cards; `feature/public/what-is-lg-subscribe/components/what-is-lg-subscribe-page.tsx` shows guide sections. These references were source-inspected for this guide.

Keep section content within `container-page`, use existing responsive spacing and red calls to action, and check desktop and mobile after visual changes. The public marketing site has its own warm neutral and red palette; backoffice defaults do not apply here.

- Backoffice: `/backoffice/analytics/` in `app/(backoffice)/backoffice/(protected)/analytics/page.tsx` uses a light gray page, white sections, compact Thai shadcn date/month pickers and shared `Button`. Tables own their border and surface. Desktop/mobile filters wrap; charts/tables scroll within their section. `/backoffice/auth/login/` uses `feature/backoffice/components/backoffice-login.tsx`. Private pages belong in `(protected)` and check the session again before reading data. Analytics was checked locally at desktop (1280px) and mobile (390px), including login/logout, month shortcuts, date filtering and keyboard focus; public marketing colors/layout remain defined by the public shell.
- Source/Google tables use `feature/backoffice/components/report-table.tsx` for the shared heading and surface. Below 640px each row becomes a labeled vertical summary; desktop keeps the table. Daily visits and top pages use the same component. All metrics remain visible on phones without table-wide horizontal scrolling. `traffic-breakdown.tsx` separates website source/campaign/device signals; `google-reports.tsx` separates Ads, GA4 and sync status. Missing Google snapshots show a waiting state rather than invented zeros. Public consent uses `components/tracking-consent.tsx` and shared `Button`, below the existing promotional dialog (z80/81) and above the mobile dock. Cookie choices can be reopened from the fixed small button.

Historical views: the source navigation jumps to website or Google data. For periods before first-party collection started, website totals use “—” and the empty daily list/chart is omitted; imported Google history stays visible. Mobile rows use labeled summaries below 640px.

Calendar controls: `components/ui/calendar.tsx` and `popover.tsx` use the shadcn New York/Radix registry; `thai-calendar.tsx` supplies Thai weekday/month names, Buddhist years, Thai screen-reader labels, and shared shadcn Select dropdowns. `thai-date-picker.tsx` provides shared date/month fields, and `feature/backoffice/components/analytics-date-filters.tsx` uses them for every analytics filter. Civil dates stay Gregorian ISO in submitted queries and use Asia/Bangkok for selection/display.

Backoffice navigation: `feature/backoffice/components/backoffice-shell.tsx` is the authenticated shared shell: desktop sidebar, sticky header, shadcn Sheet mobile menu, active route, identity and logout. LINE pages require the database user’s `line.view` permission. LINE uses real section anchors instead of placeholder menu items. Thai calendars use a white surface explicitly because portal content inherits public theme tokens.

Responsive review (development): login, analytics and LINE checked at 320, 390, 768 and 1280px. No page-level horizontal overflow in the rendered data/empty states; LINE free-text fields wrap long messages and identifiers. Section anchors leave space for the sticky header.

Public mobile review: all eight static/public pages and all 68 published product detail routes checked at 320px. Product detail single-column grids use `grid-cols-1` (minmax(0,1fr)); model/title text can wrap and the price row wraps. `feature/public/authorized/components/authorized-page.tsx` uses a constrained single-column profile grid and smaller mobile agent code. Both fixes preserve desktop layouts and were visually checked with gallery navigation.

Login password field: shared Button eye toggle with Thai accessible labels, pressed state and 44px touch target; password stays masked initially. Signed session and cookie last 24 hours from login.

Backoffice menu and permissions: `lib/backoffice/permissions.ts` is the canonical menu/permission registry. The shell groups reports, LINE and user administration and contains only backoffice links. `line-directory.tsx` shares search, pagination and responsive ReportTable for LINE users/messages; `users-manager.tsx` provides creation and permission editing. Shared `components/ui/password-input.tsx` supplies the eye toggle for login and user passwords. Google reports have their own `/backoffice/google/` route and pass the form action to the existing Thai date filters. Pages and API handlers verify permissions before reading/writing data; hidden menus alone are not access control.

Date filters: one desktop row with monthly selection/apply on the left and start/end/apply on the right. Six recent-month shortcuts live inside the month popover. At narrow widths, the same shared controls stack and the range uses two columns with a full-width submit button. Both website and Google reports reuse this layout.
